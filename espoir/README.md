## 실행

```bash
python espoir_monitor.py                 # 60분 간격, 17시 자동 종료
python espoir_monitor.py --interval 30   # 30분 간격
python espoir_monitor.py --end 18        # 18시 종료
python espoir_monitor.py --once          # 1회만 확인
python espoir_monitor.py --dump          # 달력 셀 구조 덤프
python espoir_monitor.py --headful       # 창 띄우고 실행
python espoir_monitor.py --test-alert    # 알림창만 테스트
```

**첫 실행 순서**

```bash
python espoir_monitor.py --test-alert              # 1) 알림창 확인
python espoir_monitor.py --once --dump --headful   # 2) 달력 스캔 확인
python espoir_monitor.py                           # 3) 실제 감시 시작
```

## 실행 시간 (종료 시각)

`--end` 로 종료 시각을 지정합니다. **`--end 0` 이면 무제한 실행**입니다.

```bash
python espoir_monitor.py                    # 17시 종료 (기본)
python espoir_monitor.py --end 22           # 22시 종료
python espoir_monitor.py --end 0            # 무제한 (Ctrl+C 로 종료)
python espoir_monitor.py --end 0 --interval 30   # 30분 간격 무제한
```

### 무제한 모드 (`--end 0`)

사용자가 직접 멈출 때까지 계속 실행합니다. **자정을 넘겨도 종료되지 않으며**,
날짜가 바뀌면 확인 대상이 자동으로 갱신됩니다(재시작 불필요).

```
감시 시작 v2026-07-24n (간격 30분, 오늘 포함 15일, 무제한 실행 (Ctrl+C 로 종료))
...
다음 확인: 00:21 (무제한 실행 중)
```

종료는 `Ctrl+C` 입니다.

### 종료 시각 지정 모드

마지막 대기가 종료 시각을 넘기지 않도록 대기 시간을 잘라냅니다.

| 시작 | 종료 지정 | 동작 |
|------|-----------|------|
| 16:10 | `--end 17` | 16:10 → 16:40 확인 후 17:00 종료 |
| 18:30 | `--end 17` | 실행하지 않음 (종료 시각 경과) |
| 22:00 | `--end 0` | 22:00 → 22:30 → 23:00 → … 계속 |

## 알림 (예약 가능 발견 시)## 알림 (예약 가능 발견 시)

작은 대화상자는 다른 창에 가려지기 쉬워서, 기본값을 **전체화면 경보**로 설정했습니다.
네 가지가 동시에 동작합니다.

| 효과 | 내용 |
|------|------|
| **전체화면 점멸 경보창** | 빨강 ↔ 주황 배경이 0.55초마다 번갈아 깜빡임, 항상 최상위 |
| **반복 알람음** | 12회 반복 (Windows 2음 비프 / macOS Glass / Linux paplay) |
| **음성 안내** | "예약 가능한 날짜가 열렸습니다" TTS |
| **예약 페이지 자동 열기** | 1.2초 후 기본 브라우저로 예약 페이지 열림 |

### 경보 진행 순서

| 시점 | 동작 |
|------|------|
| 0초 | 전체화면 경보 + 알람음 + 음성 안내 |
| 4초 | **예약 페이지가 브라우저에 자동으로 열림** |
| +0.6초 | **경보창이 스스로 닫힘** → 예약 화면이 바로 보임 |

경보창이 예약 화면을 가리지 않도록, 브라우저를 연 뒤 자동으로 닫힙니다.
**[예약 페이지 열기]** 버튼을 직접 눌러도 동일하게 열리고 닫힙니다.
`Esc` 또는 [닫기]로도 종료되며, 아무 조작이 없으면 15분 후 닫힙니다.

경보창은 **별도 프로세스**로 뜨므로 창을 닫지 않아도 감시는 계속 진행됩니다.

### 미리보기 (두 가지)

```bash
python espoir_monitor.py --test-alert     # 경보창 모양만 확인
python espoir_monitor.py --simulate-hit   # 실제 발견 경로를 그대로 재현 (권장)
```

`--test-alert`는 현재 프로세스에서 창만 띄웁니다.
`--simulate-hit`은 **실제 예약 발견 시와 완전히 동일한 경로**로 동작합니다.

| 단계 | --test-alert | --simulate-hit |
|------|:---:|:---:|
| 경보창 표시 | O | O |
| **별도 프로세스로 실행** | X | **O** |
| 알람음 / 음성 | O | O |
| 예약 페이지 자동 열기 | O | O |
| **텔레그램 / 웹훅 전송** | X | **O** |

실제 상황에서 경보가 확실히 뜨는지 검증하려면 `--simulate-hit`을 쓰세요.
별도 프로세스 실행이 실패하는 환경(경로에 공백 등)도 여기서 걸러집니다.

### 강도 조절 (파일 상단)

| 항목 | 설명 |
|------|------|
| `ALERT_MODE` | `"window"` 전체화면 경보(기본) / `"dialog"` 기본 대화상자 / `"both"` 둘 다 |
| `ALERT_SOUND_TIMES` | 알람음 반복 횟수 (기본 12, `0`이면 무음) |
| `ALERT_SPEAK` | 음성 안내 사용 여부 |
| `ALERT_OPEN_BROWSER` | 예약 페이지 자동 열기 |
| `ALERT_OPEN_DELAY` | 브라우저를 열기까지 대기(초). 기본 4 |
| `ALERT_CLOSE_ON_OPEN` | 브라우저를 연 뒤 경보창 자동 닫기 (기본 True) |
| `ALERT_AUTO_CLOSE` | 경보창 자동 닫힘(초). `0`이면 직접 닫을 때까지 유지 |

자리를 오래 비우신다면 `ALERT_AUTO_CLOSE = 0`으로 두면 돌아올 때까지 화면에 남아 있습니다.

`tkinter`가 없는 환경(일부 리눅스)에서는 자동으로 기본 대화상자로 대체됩니다.
필요하면 `sudo apt install python3-tk`로 설치하세요.

## 헤드리스 실행 (기본)

기본 실행은 **headless** — 브라우저 창 없이 백그라운드에서 동작합니다.
평소에는 옵션 없이 그냥 실행하면 됩니다.

```bash

```

헤드리스에서 로그인이 막히지 않도록 다음 설정이 적용되어 있습니다.

- 일반 Chrome과 동일한 User-Agent
- 자동화 감지 플래그 비활성화 (`--disable-blink-features=AutomationControlled`)
- `navigator.webdriver` 흔적 제거
- 한국 로케일 / `Asia/Seoul` 시간대, 1440×960 뷰포트

문제가 생기면 `--headful`로 창을 띄워 비교해 보세요.

```bash

```

**경보창은 별개입니다.** 예약 가능한 날짜를 찾았을 때만 뜨며,
찾지 못하면 아무 창도 뜨지 않는 것이 정상입니다.

## 화면 깨짐 / 로그인 관련

### 화면이 깨져도 모니터링에는 문제없습니다

스캔은 **픽셀이 아니라 DOM**(태그·클래스·onclick 속성)을 직접 읽습니다.
기본 실행이 headless(창 없음)라 CSS는 아예 렌더링되지 않으므로,
레이아웃이 깨지든 말든 판정 결과는 동일합니다.

Step1의 "위 내용을 확인하고…" 클릭도 CSS 표시 여부에 의존하지 않도록
**JS로 DOM을 직접 조작**하는 방식을 우선 사용합니다.

### 진짜 위험한 건 CSS가 아니라 "빈 달력"

달력은 JS로 채워지므로, 로그인이 필요하거나 스크립트가 실패하면
**달력이 비어있는데도 "예약 가능 없음"으로 조용히 넘어갈** 수 있습니다.
이 false negative를 막기 위해 매 확인마다 진단을 수행합니다.

| 상태 | 처리 |
|------|------|
| 달력 있음 + 날짜 셀 있음 | 정상 스캔 |
| 로그인 페이지로 리다이렉트 | 자동 로그인 후 재시도 |
| 달력 없음 / 셀 0개 | 자동 로그인 후 재시도 |
| 재시도 후에도 실패 | **"확인 불가" 알림창** + 로그 기록 |

즉 **"예약 없음"과 "확인 실패"를 구분**하며, 확인 실패는 조용히 넘어가지 않고
알림을 띄웁니다. (스팸 방지를 위해 문제 알림은 1회만)

#### 로그인 링크 찾기

지정된 xpath를 최우선으로 하되, 실패에 대비해 여러 후보를 순서대로 시도합니다.

| 순위 | 셀렉터 |
|:---:|--------|
| 1 | `/html/body/div[1]/section[1]/div[2]/ul[1]/li[1]/a` **(지정 경로)** |
| 2 | `/html/body/div/section[1]/div[2]/ul[1]/li[1]/a` |
| 3 | `#btn_header_login` |
| 4 | `a[id*="header_login"]` |
| 5 | `//ul//li/a[text()='로그인']` |
| 6 | `//a[text()='로그인']` |

각 후보마다 **일반 클릭 → 강제 클릭 → JS 클릭** 순으로 폴백합니다.
화면이 깨져 요소가 숨김 처리되어도 클릭할 수 있습니다.
로그에 어떤 방식으로 성공했는지 남습니다.

```
로그인 링크 클릭 성공 (일반, #btn_header_login)
```

#### 화면 깨짐 대응

페이지 이동 후 `document.styleSheets`가 실제로 로드됐는지 확인하고,
비어 있으면 **1회 새로고침**합니다. 그래도 안 되면 경고만 남기고 진행합니다.

```
경고: 스타일이 적용되지 않은 상태 (동작에는 지장 없음)
```

스캔은 픽셀이 아니라 DOM을 읽으므로 화면이 깨져도 판정 결과는 동일합니다.
최종 실행은 헤드리스이므로 렌더링 자체가 없어 영향이 없습니다.

#### 제출 버튼

```python
LOGIN_SUBMIT_XPATH = "/html/body/div[1]/section/div[2]/form/div[5]/button"
```

실패 시 로그인/submit 버튼 → 엔터키 순으로 폴백합니다.

### 로그 출력 위치

진행 단계 `[1/6]`~`[6/6]`은 실시간으로 표시되고,
집계 결과는 **사이클 마지막에 "결과" 블록으로 정리**되어 출력됩니다.

[16:56:24]       당월 달력 표시됨 (셀 31개)

[16:56:29] 확인 대상 7월23~31일 (9일): 마감 9 / 오픈예정 0 / 예약가능 0

예약 가능한 날짜를 찾으면 마지막 줄이 바뀝니다.

```

```

`--dump` 셀 덤프와 `id=b_*` 개수 같은 세부 진단은 `monitor_log.txt`에만
기록됩니다. 콘솔에서도 보려면 `--verbose`를 붙이세요.

### 날짜 상태 분류 (실측 마크업)

```html
<button type="button" id="b_2" disabled="disabled">2</button>        <!-- 마감 -->
<button type="button" class="unableday" disabled="disabled">7</button><!-- 오픈예정 -->
```

| 상태 | 판별 조건 |
|------|-----------|
| **예약가능** | `disabled` 없음 (클릭 가능) → **알림 대상** |
| **마감** | `disabled` + `unableday` 클래스 없음 |
| **오픈예정** | `disabled` + `class="unableday"` |

**알림 판정은 `disabled` 여부만 사용합니다.** `id`나 클래스는 판정에 쓰지 않으므로
마크업이 조금 달라져도 안전합니다. `id=b_*` 개수는 참고용으로만 기록합니다.

### 두 줄로 나뉜 이유

- **첫 줄** — 그 달 전체 31일의 상태 분포
- **둘째 줄 (확인대상)** — 미래 15일 평일만 추린 **실제 감시 대상**

전체 집계에는 이미 지난 날짜도 섞여 있습니다(7월의 마감 31에는 7/1~7/22 포함).
따라서 **"확인대상" 줄이 실질적인 감시 상태**입니다.

취소가 발생하면 이렇게 바뀝니다.

```
2026.08 집계: 전체 31일 | 마감 5 | 오픈예정 25 | 예약가능 1  (id=b_* 6)
  확인대상 5일: 마감 3 / 오픈예정 1 / 예약가능 1
  예약가능 상세: 4일(id=b_4, cls=없음)
```

로그는 매 실행마다 파일에 **누적**되므로, 며칠간 추이를 되돌아볼 수 있습니다.

### 로그인 상태 판정

이 사이트의 헤더 로그인 버튼은 다음과 같은 형태입니다.

```html
<a href="#" id="btn_header_login" onclick="...">로그인</a>
```

`href`가 `#`이고 실제 이동은 JS로 처리되므로, **링크 주소로 로그인 여부를 판단하면 안 됩니다.**
따라서 요소 id를 기준으로 판정합니다.

| 조건 | 판정 |
|------|------|
| `#btn_header_logout` 또는 logout 링크 존재 | 로그인됨 |
| `#btn_header_login` 존재 | **로그아웃 상태** |
| 둘 다 없음 | 판별 불가 |

매 확인마다 `로그인 상태: 로그인됨` 형태로 로그에 기록됩니다.

### 로그아웃 상태에서는 결과를 신뢰하지 않습니다

로그아웃 상태에서도 달력은 표시되지만 **모든 날짜가 마감(`disabled`)으로 보일 수 있습니다.**
이 상태를 그대로 믿으면 취소 자리가 나와도 영원히 알림이 울리지 않습니다.

그래서 로그아웃이 감지되면 결과를 버리고 로그인 후 다시 확인하며,
로그인에 실패하면 "예약 없음"이 아니라 **확인 실패로 알립니다.**

```
로그인 상태: 로그아웃 상태
로그아웃 상태 -> 로그인 후 재확인 (비로그인 달력은 전부 마감으로 보일 수 있음)
```

### 로그인 정보 설정

```bash
# Windows PowerShell
$env:ESPOIR_ID="본인아이디"
$env:ESPOIR_PW="본인비번"

# macOS / Linux
export ESPOIR_ID="본인아이디"
export ESPOIR_PW="본인비번"
```

CMD에서는 `set ESPOIR_ID=본인아이디` 형식이며, 설정하지 않으면 파일 상단의
`ESPOIR_ID` / `ESPOIR_PW` 값을 사용합니다. 예시값(`id11`) 그대로면 시작 시 경고가 표시됩니다.

## 로그인 URL에 대해

로그인은 아모레퍼시픽 통합 인증(`one-ap.amorepacific.com`)을 거칩니다.
그 인증 URL을 **하드코딩하면 안 됩니다.** 아래 값들이 일회성이기 때문입니다.

| 파라미터 | 성격 |
|----------|------|
| `sessionDataKey` | 인증 세션 1회용 키. 짧은 시간 내 만료 |
| `sid` | 세션 식별자 |
| `cid` | 클라이언트/방문 식별자 |

대신 스크립트는 **사이트가 매번 새 인증 URL을 발급하도록** 진입점을 구성합니다.

```
https://www.espoir.com/oauth2AuthorizeUser?reset=true&cid=&sid=&redirectUri=<예약페이지 URL>
```

이 주소로 들어가면 espoir가 새 `sessionDataKey`를 포함한 인증 URL로 자동 리다이렉트하고,
`redirectUri` 덕분에 **로그인 성공 즉시 예약 페이지로 복귀**합니다.
(직접 주신 URL의 `state` 안에 있던 redirectUri와 동일한 값으로 생성됨을 확인했습니다.)

굳이 특정 URL로 시작해야 한다면 아래처럼 지정할 수 있지만, 만료 시 실패합니다.

```bash
python espoir_monitor.py --login-url "https://one-ap.amorepacific.com/auth/login?..."
```

### 로그인 폼 인식 방식

인증 페이지에는 네이버·카카오·애플 등 소셜 로그인 버튼이 함께 있습니다.
엉뚱한 입력란을 잡지 않도록 **비밀번호 입력란을 먼저 찾고, 같은 `<form>` 안의
첫 번째 텍스트 입력란을 아이디 칸으로 판단**합니다.
로그인 후에는 espoir 도메인 복귀 + 로그아웃 링크 존재를 함께 확인해 성공으로 처리합니다.

## "예약 가능" 판정 기준

실측으로 확인된 달력 셀 구조입니다.

```html
<td><button disabled>24</button></td>              <!-- 마감 -->
<td><button class="today" disabled>23</button></td><!-- 오늘 -->
<td><button class="unableday" disabled>8</button></td><!-- 예약 범위 밖 -->
```

이 사이트는 **마감을 클래스가 아니라 `disabled` 속성으로 표시**합니다.
따라서 판정은 `disabled`를 1차 기준으로 삼습니다.

1. 셀 안에 `<a>` / `<button>`이 있음
2. **`disabled` / `aria-disabled`가 없음** ← 핵심 기준
3. 클래스가 `unableday`, `soldout`, `impossible`, `dimmed`, `blind`가 아님 (보조)

> 초기에는 `end`, `off`, `none` 같은 짧은 키워드도 썼으나,
> `end`가 `weekend`·`openday`에도 부분일치해 **예약 가능한 날을 놓칠 위험**이 있어
> 정밀한 값만 남겼습니다.

`--dump` 출력에는 X 판정의 사유가 표시됩니다.

```
  *X 24일 | td. | inner=button. [disabled]              <- 마감
   X  8일 | td. | inner=button.unableday [disabled]     <- 예약 범위 밖
   O 30일 | td. | inner=button.                         <- 예약 가능
```

### 실제 예약 가능 범위

`unableday` 클래스의 경계를 보면 실제 예약 상한을 알 수 있습니다.
2026-07-23 기준으로 8/6까지는 일반 셀, 8/7부터 `unableday`였습니다.

| 날짜 | 상태 |
|------|------|
| 8/6 (오늘+14일) | 예약 범위 안 (마감 상태) |
| 8/7 (오늘+15일) | `unableday` — 범위 밖 |

즉 실제 상한은 **오늘+14일**입니다. `DAYS_AHEAD = 15`여도 마지막 하루는
항상 `unableday`로 걸러지므로 오탐이 생기지는 않습니다.
로그를 깔끔하게 하려면 `DAYS_AHEAD = 14`로 줄여도 됩니다.

## 월 이동 (다음 달 확인)

다음/이전 달 버튼은 **클래스도 텍스트도 없는 순수 `<button>`**입니다.
따라서 두 가지 방법을 순서대로 시도합니다.

1. 확인된 정확한 XPath (`NEXT_XPATH` 상수)
   ```
   /html/body/div/form[5]/.../div/div[1]/button[2]
   ```
   `button[1]`이 이전 달, `button[2]`가 다음 달입니다.
2. **구조 기반 탐색** — 달력 표에서 위로 올라가며 "표 바깥에 있는 버튼"이
   2개 이상인 컨테이너를 찾아 마지막 버튼(다음) 또는 첫 버튼(이전)을 클릭

클릭 후에는 **달력 내용 지문을 비교해 실제로 월이 바뀌었는지 확인**합니다.
바뀌지 않으면 다음 방법으로 넘어갑니다.

사이트 개편으로 XPath가 바뀌면 2번 방식이 자동으로 동작하며,
필요하면 `NEXT_XPATH` 상수만 새 값으로 교체하면 됩니다.

### 버튼이 비활성인 경우

다음 달 버튼이 `disabled`면 **아직 오픈되지 않은 달**이라는 뜻입니다.
이 경우는 오류가 아니라 "예약 가능 없음"으로 처리하며 경고 알림을 띄우지 않습니다.

| 상황 | 처리 |
|------|------|
| 이동 성공 | 정상 스캔 |
| 버튼 비활성 | 오픈 전 → 예약 없음으로 처리 (알림 없음) |
| 버튼 못 찾음 / 달력 안 바뀜 | **확인 실패 → 경고 알림** |

## 설정 항목 (파일 상단)

| 항목 | 설명 |
|------|------|
| `DAYS_AHEAD` | 확인할 일수, 오늘 포함 (기본 15) |
| `END_HOUR` | 기본 종료 시각 (기본 17, `--end 0` 이면 무제한) |
| `SKIP_WEEKEND` | 토/일 제외 (기본 True) |
| `TRY_WITHOUT_LOGIN` | 먼저 비로그인으로 시도 (기본 True) |
| `AUTO_FALLBACK_LOGIN` | 실패 시 로그인 후 재시도 (기본 True) |
| `NOTIFY_ONLY_ON_CHANGE` | 새 날짜가 생겼을 때만 알림 |
| `RSV_URL` | 퍼스널 레슨은 `i_sProgramcd=pcs` → `pls` |
